# Dashboard — 대시보드 스펙 (SSOT)

> Status: **agreed spec** (2026-07-31, 그릴링 세션 합의; 컨셉 B 전환 2026-07-31). 구현 전 목업 이터레이션 중.
> 목업: `docs/mockups/dashboard-home-tab.html`

## 0. 정체성

- **현재 노트북 스코프** 대시보드(컨셉 B, 2026-07-31 전환 — §5). 노트북은 한
  SQLite 파일 안의 행이므로, 추후 수요 시 스코프 토글("이 노트북/전체")로 총괄
  조망을 회수할 수 있다 (쿼리의 `workspace_id` 필터 문제일 뿐).
- 본업은 **런처** — "오늘 뭐 하지, 다음에 뭐 하지, 뭐가 등록됐지"의 가이드.
  조망(overview)은 부수적으로 따라온다.
- **압박 최소화**가 헤더의 설계 원칙: 스탯·숫자로 다그치지 않는다 (긴급 신호는 상태 탭 담당).
- **데스크톱 전용** v1. 모바일은 별도 트랙 (MobileHome이 이미 모바일 런처 역할).
- **유기적 시스템** — 모든 탭은 조망(보기)·진입(노트 열기)·생성(새 노트)이 가능하다. 생성은 각 탭의 축을 프리필한다.

## 1. 동선

- **고정 대시보드 탭** — 탭바 첫 자리에 상주하는 닫을 수 없는 대시보드 탭. 아이콘은 lucide `Home`
  하나만 (상태점·이모지·텍스트 없음, aria-label/title로 접근성 유지). 노트 탭들은 그
  옆에 열린다.
- 구현 노트: `openTabs`는 노트 ID 배열이므로 탭 시스템의 **다형화**가 필요하다 — 대시보드 탭은
  ID가 아니라 고정 슬롯이라 닫기·전체 닫기·영속화(localStorage 등)·`activeNote` 파생 로직
  전부에 "대시보드면 예외" 특수 분기가 들어간다. 작업량을 감수하고 컨셉 B로 확정
  (2026-07-31, §5).
- 부팅 = **대시보드 탭이 활성 상태인 것이 자연 기본** — 탭바 첫 자리가 항상 대시보드이므로 별도
  "시작 화면" 설정은 불필요하다.
- 이탈: 다른 탭으로 전환하면 그 탭의 노트가 보인다 (탭 전환이 곧 이탈).
- 노트북 전환 시 대시보드 탭도 함께 전환된 노트북의 내용을 보여준다 (대시보드 탭은
  노트북별 별도 상태가 아니라 "현재 노트북의 대시보드"을 항상 렌더링).
- 대시보드 콘텐츠는 **카드 래퍼 없이 캔버스 직접** — `App.tsx`의 `showHome` 분기가 감싸던
  `card card-reading` 라운드박스는 제거됨(HomeTab이 이미 자체 root에
  flex:1/minHeight:0/overflow:hidden을 갖고 있어 래퍼는 레이아웃 중복이었다). 상하 여백은
  HomeHeader 자체 패딩이 흡수.

## 2. 스키마 (마이그레이션 3개: v28 신설 → v29 due_at 폐지 → v30 remind 플래그)

> **핵심 규칙 (2026-08-01 오너 확정, 재확정 — §5): 노트 날짜는 중립 기록 정보다.**
> 과거 날짜는 정상이지 "지남"이 아니다. "마감 취급"(긴급도 정렬·빨강·상태탭 레인·달력
> ⏰뱃지) 표시 규칙은 **전면 폐지**됐다 — 종료일이 과거라는 사실 자체는 더 이상 아무
> 신호도 아니다. 노트의 날짜는 여전히 **시작일(`year`/`month`/`day`) + 종료일
> (`end_year`/`end_month`/`end_day`) 두 축뿐**이지만("기간의 끝 = 처리 기한", 같은 개념을
> 두 필드로 들고 있지 않는다는 원칙은 유지), 그 위에 표시 효과를 얹는 조건이 바뀌었다.
>
> **`notes.remind` (v30)**: 노트별 명시 opt-in 플래그(`INTEGER NOT NULL DEFAULT 0`). 이
> 플래그가 켜져 있고 **그리고** 종료일이 연월일 풀 정밀도로 **오늘보다 과거**일 때만
> (완료 컬럼 제외) 그 노트가 상태탭 칸반 컬럼 안에서 맨 위로 뜨고 모서리에 작은 빨간
> 점이 붙는다 — 시간 윈도우([오늘-30일, +∞) 같은 컷오프)는 없다: remind 를 켠 사용자의
> 의도가 곧 신호이므로, 1598년에 끝난 노트라도 켜져 있으면 그대로 핀이 붙는다. 날짜가
> 없으면 플래그는 저장만 될 뿐 아무 효과가 없다(끄지 않아도 무해 — 날짜를 다시 채우면
> 이전 의도가 되살아난다). 판정 지점은 Rust `repo::dashboard::is_pinned` 하나(정렬),
> TS `board/status.ts::isPinned`(클라 재정렬 시 동일 판정 재현, board/calendar 링크
> 참고) — 달력 탭은 이 표시 효과와 완전히 무관하다(아래 참고).

| 컬럼 | 의미 | 축 |
|---|---|---|
| `notes.end_year/end_month/end_day` (NULL) | 사건의 종료 시점 (기간) | 사건 축 확장 (기간) |
| `notes.remind` (v30, `INTEGER NOT NULL DEFAULT 0`) | "알려줘" opt-in 플래그 — 칸반 핀/빨간 점의 필요조건 중 하나 | 표시 우선순위 축(사건 축과 독립) |
| ~~`notes.due_at`~~ | ~~언제까지 할 것~~ | **폐지(v29, 2026-08-01)** — end_* 로 이관 후 컬럼 드롭 |

- 체크박스 항목에는 **개별 날짜 없음** — 노트의 종료일을 상속한다(마감 취급 개념 자체가
  없으므로 상속할 "취급"도 없다 — 그냥 같은 종료일이 적용될 뿐).
- 기간이 있으면 기존 사건 날짜 라벨은 **"시작일"**로 바뀌어 시작일–종료일 쌍으로 읽힌다.
- **이관(v29)**: 기존 `due_at` 값은 ① `end_*`가 비어 있으면 종료 트리플로 이관, 시작이
  종료보다 뒤라면(정밀도 부족분은 시작=가장 이름/종료=가장 늦음으로 비교) 시작도 같은
  날짜로 당겨 end⇒start 불변식을 지킨다 ② `end_*`가 이미 있으면 역사적 종료가 우선 —
  `due_at`은 버려진다. `db/migrations.rs` V29_SQL 참고.
- **달력 탭은 중립이다**: 사건/기간 칩은 어떤 경우에도 색이나 ⏰가 붙지 않는다 — 핀/빨간
  점은 상태탭 칸반 전용 표시(위 규칙)이고, 달력은 "무압박" 원칙에 따라 날짜를 있는
  그대로만 보여준다(`home/calendarLayout.ts` 에는 더 이상 deadline 관련 타입/함수가 없다).
  예외 하나(2026-09-08): remind 표시 — 제목이 보이는 곳(월간 칩·기간 막대·하루 패널 카드/시간축)은
  **제목 뒤 작은 벨**(`calendar/RemindBadge.tsx`, currentColor 상속), 제목이 없는 연간 뷰는 칸
  모서리의 폴더색 점(§3.3). 둘 다 "지났다/급하다"가 아니라 "알려달라고 켜 둔 것"을 표시하는 것이라
  원칙의 대상이 아니다.
- **모바일 피드는 이 축에 관여하지 않는다**: `sync_server::handlers::NoteListItem`(모바일 웹
  피드)은 의도적으로 `end_*`/`remind` 를 노출하지 않는다 — 모바일 쪽 종료일 입력 UI가 아직
  결정되지 않았기 때문(2026-08-01). 데스크톱 IPC(`NoteSummary`/`BoardNote`)만 두 필드를
  나른다.

### 3.2 상태 탭 (칸반+, 할일 통합, 구 "작업 탭")
- **새 상태 추가 진입점 (2026-09-08)**: 칸반 열 행의 **맨 오른쪽 좁은 슬롯**(`board-add-status-slot`,
  "+" → 인라인 입력, Enter/blur 확정·Escape 취소). 예전에 대시보드 탭 행 오른쪽(폴더 필터 옆)에
  있던 "상태 추가" 버튼과 상태 필터 팝오버는 칸반 잔재라 제거 — 상태 필터링은 사이드바
  FilterStrip 에만 남는다. `status_add_locked` 가 켜져 있으면 슬롯 자체가 없다.
할일 탭과 칸반을 **합친 단일 탭**. 단위 구분: 칸반 보드=노트, 카드 내부=체크 항목.
- 컬럼 = 현재 노트북의 status 체계 그대로 (내장 3종 + 그 노트북의 커스텀
  상태명). 이름 병합은 없다 — 노트북 스코프에서는 병합할 대상이 없다.
- 드래그 = `set_status`.
- **컬럼 내 정렬 = 일정(schedule)**: `remind` 켜짐 + 종료일이 풀 정밀도로 과거인 노트가
  먼저(완료 컬럼 제외) → 나머지는 종료일 오름차순(날짜 없으면 맨 뒤) → updated_at 최신
  (판정은 `is_pinned`, §2). "최근 수정"/"제목" 정렬 모드로 바꿔도 핀은 항상 그 컬럼 맨
  위에 고정된다(BoardColumn.tsx — pin은 정렬 모드보다 우선).
- 카드 접힘(기본): 제목 + 날짜 범위 텍스트(항상 표시, 중립) + 미체크 개수. 핀된 카드는
  모서리에 작은 빨간 점.
- 카드 펼침: 체크박스 인라인 **토글 가능**. 드래그 시작하면 자동 접힘.
- 체크 토글 = 서버에서 해당 섹션 `body_md`의 그 줄 `- [ ]`↔`- [x]` 치환.
  열려 있는 에디터와의 충돌은 기존 `remoteNoteWrite` 경로로 리로드.

  `lib/dayMarks.ts`·`lib/lunar.ts`(Intl `dangi` 달력)가 맡는다. 표시일 자체(내 기념일·불러온 캘린더·숨김)는

### 3.4 타임라인 탭
- **가로 연대기 풀버전**: 가로축=년, 노트=점, 기간 노트=가로 막대, era(시대)=배경 밴드.
- 상단에 **미니맵 브러시 바**: 전체 범위(예: 1930–2026) 대비 아이템 위치를 흐린 막대로 축약
  표시하고, 현재 뷰포트를 나타내는 브러시 창(드래그로 이동)을 겹쳐 올린다. 브러시 이동/줌은
  메인 캔버스의 줌·팬과 연동 — "지금 전체 중 어디를 보고 있는지"를 항상 인지시킨다.
  시각 언어는 사이드바 `TimelineFilter`(연도 슬라이더)와 동일하게 맞춘다: 얇은 라인
  트랙 + accent 손잡이가 달린 브러시(핸들) + 항목 위치 눈금.
- 줌/팬 (10년↔1년 스케일, 브러시 창 크기 = 줌 수준). 레이아웃 충돌 회피(레인 배치)·가상화
  필요 — 난도 최고 트랙.
- **상단 기준 정렬 (2026-08-01 QA 고정)**: 정상 레인 모드·강등(연도-버킷 히스토그램) 모드
  모두 같은 top edge(`LANE_TOP_PAD`)를 기준으로 아래로 쌓인다 — bottom 기준 포지셔닝
  금지. 강등 모드의 `BucketMark`가 바닥 축(`bottom: AXIS_HEIGHT+…`)에서 자라 올라오던
  것이 "아이템이 전부 바닥에 붙어 보이는" 버그의 원인이었다. 규칙은
  `src/components/home/timeline/layout.ts` 상단 "VERTICAL ANCHOR RULE" 주석에
  명문화되어 있고, `TimelineTab.test.tsx`가 두 모드 모두 computed `top === "36px"`임을
  회귀 고정한다.
- 빈 영역에서 **간트식 가로 드래그** → 실시간 고스트 기간 막대(양끝 연도 라벨) → 새 노트(기간 프리필).
  기존 점/막대 아이템 클릭 = 노트 진입(hover로 강조해 진입을 암시).
- **휠 규약 (2026-09-08 개정)**: 가로 휠(틸트 휠·트랙패드) = 뷰 창을 시간축으로 팬 ·
  세로 휠 = 레인 세로 스크롤(캔버스가 `overflow:auto` 를 소유) · **Ctrl/Cmd+휠 = 커서 기준 줌**.
  이전에는 모든 휠이 줌이었고 `preventDefault` 가 무조건 걸려 ⓐ 가로 휠이 `deltaY === 0` →
  "not < 0" 으로 읽혀 노치마다 **축소**됐고 ⓑ 레인이 넘쳐도 스크롤바를 끄는 것 말고는 아래를
  볼 수 없었다. 같은 ⓐ 결함이 있던 **지도(`useMapPanZoom`)·이미지 미리보기(`ImagePreview`)도 같은
  규약으로 통일**했다 — 가로 휠 = 팬, 맨 세로 휠은 소비하지 않아 그것들을 품은 스크롤
  컨테이너(설정의 지도 미리보기, 노트 에디터)가 대신 스크롤되고, 줌은 Ctrl/Cmd+휠이다. 그 둘의
  modifier 경로는 잠금(`isLocked`)/`fit` 상태에서도 `preventDefault` 를 지켜 브라우저 자체
  Ctrl+휠 페이지 확대가 겹쳐 뜨지 않게 한다.
- 기존 사이드바 히스토그램은 그대로 (역할 다름: 필터 vs 조망).

### 3.5 지도 탭
- 기존 지도 뷰 승격 (lat/lng + note_regions) + 연도 슬라이더 연동.
- **기본 뷰 = 노트북의 기본 위치**(설정 › 지도, `default_map_location`, 팩토리 값 서울). 같은
  세션에 보던 뷰가 있으면(`homeMapView`, 줌 상한 이내) 그 뷰로 연다. **노트 전체 맞춤(fit)은
  사용자가 필터를 바꿨을 때만** 돈다(GRILL-2026-10-19 R5) — 연도 히스토그램 도착
  (`applyYearCounts` 가 전체 범위를 다른 전체 범위로 옮김)이나 노트 쓰기로 인한 재조회
  (`noteQueryVersion`)는 카메라를 움직이지 않는다. 연도 축은 좁혀졌을 때만 필터 서명에 들어간다.
  맞출 노트가 없으면 기본 위치로 간다. **노트북을 바꾸면 맞춤 대신 세계 뷰**(줌 1, 위도 20, 경도 =
  기본 위치의 경도 — 기본 지역이 화면 가운데)로 간다(GRILL-2026-10-19 R15). `default_map_location`
  은 기기 전체 키 하나라 노트북별 기본 위치가 생기기 전까지의 동작이다.
- **아무것도 선택 안 했을 때 오른쪽 패널 = 기본 위치 주변 노트**(기본 위치를 고른 것처럼). 마커
  클릭과 같은 경로(`nearestTo`/`nearestAround`, 로드된 마커 중 최근접 8개, 거리순)를 기본 위치
  기준으로 돌린다. 목록 항목 클릭 = 그 노트로 전환, 닫기 = 기본 위치 목록으로 복귀. 주변에 노트가
  없으면 조용한 빈 줄 + 마커 안내. 첫 마커 조회 중에는 빈 상태 대신 '불러오는 중'.
- **팬·줌 빈공간 클램프 (2026-08-01 QA 고정)**: d3 geoMercator 기본 투영은 항상 가로
  변 기준 정사각형이라, 세로가 넓은 창에서는 최소 줌에서도 위아래 빈 공간이 드러나고
  팬도 경계를 넘어갈 수 있었다. `geometry.ts`의 `minCoverZoom`/`clampMapTransform`
  (화면비 반영, 줌 하한 + x/y 팬 한계)을 WorldMap의 모든 transform 생성 지점과
  `useMapPanZoom`의 드래그·휠 줌 경로에 적용해 고정.
- **생성 중 뷰포트 불변 원칙 (2026-08-01 QA 고정)**: 빈 지점 클릭·검색 선택·생성 확정
  어느 단계에서도 지도의 배율/중심이 저절로 움직이지 않는다. 임시 핀은 이미 화면에
  보이는 지점에 찍히므로 `panTo()` 호출이 불필요했고(제거), 생성 확정 후 노트 재조회
  (`noteQueryVersion`)는 fit-to-notes 를 아예 부르지 않는다 — 맞춤은 필터 서명이 바뀔 때만
  돈다(위 기본 뷰 항목, 2026-10-19 R5 로 예전 1회 건너뛰기 가드 `skipNextFitRef` 는 제거).
- 좌상단 **장소 검색**(지오코딩) → 결과 목록 → 클릭 시 지도에 임시 핀 표시 → 새 노트
  (lat/lng 프리필, 빈 지점 클릭 생성과 동일한 흐름 재사용). 지오코딩 소스는 구현 트랙에서
  기존 지도 스택에 맞춰 결정.
- 빈 지점 클릭 → 임시 핀 표시 → 새 노트(lat/lng 프리필). 마커 = 기존 노트 진입(클릭 시 이벤트
  버블링 차단으로 빈 지점 클릭과 구분).
- 마커 클릭 → **오른쪽 패널(280px)**: 선택 노트 상세 + **최근접 N 주변 노트** 1줄 목록(거리
  계산은 로드된 마커로 클라 계산, 폴더 색 점 + 제목 + 거리 + 연도). (초기 기획의 하단
  필름스트립·썸네일 카드는 Wave D 에서 오른쪽 패널로 바뀌었다.)
- 목록 항목 클릭 = 그 노트로 선택 전환(**항목→항목 연결 탐색**, 뷰포트는 움직이지 않는다).
  더블클릭 = 노트 이동.
- 클러스터링·경로 그리기는 v1 제외.

### 3.6 공간(Space) 탭

사용자가 직접 배치하는 무한 캔버스. 상태 탭의 칸반(내부 식별자 `board`)과 **완전히
다른 개념**이다 — 스키마·커맨드·UI에서 "board"를 쓰지 않는다.

- **홈** = 공간 탭에 들어갔을 때 기본으로 열리는 공간. 앱 시작 화면은 건드리지 않는다(§1).

  공간이 0개인가로 판단하지 않는다 — 사용자가 마지막 공간을 지워도 템플릿이 되살아나지 않는다.
- 상세 계약: [PLAN-2026-08-15-space-tab.md](./PLAN-2026-08-15-space-tab.md).

- 제안 행(`kind='overlap'`)은 `dashboard_graph` 가 연관 엣지를 계산하며 쓴다 — 그래서 제안은
  **그래프 로드가 끝난 뒤** 읽는다(첫 진입 0건 방지). 연결·절단·수락·무시 뒤의 재조회도 같은 길이다.
- 제안 모달은 없다. 좌상단 `✦ 연결 제안 N건` 칩은 **선택 중에만** 보이는 건수 바로가기 — 누르면
  선택을 풀어 패널이 제안 목록으로 돌아간다.

## 4. 백엔드 원칙 (SCALABILITY.md 지배 원칙 준수)

**클라 상주 코퍼스 재사용 금지** — 대시보드는 처음부터 서버측 쿼리로 태어나는 첫 화면.
전 커맨드 `workspace_id: String` (필수, 현재 노트북). 추후 스코프 토글(§0)을 위해
`Option<String>`(None = 전체)으로 복귀하는 것이 싼 구조로 짜 둔다.

## 5. 그릴링에서 기각/보류된 것 (재론 방지)

- 홈 고정 탭 (탭 시스템 다형화) → 독립 페이지로. "부팅 시 대시보드" 설정이 같은 효과.
  → **2026-07-31 번복, 컨셉 B로 채택** (아래 항목 참고).
- 할일 플랫 리스트 단독 탭 → 칸반과 겹침 → 상태 탭으로 통합. 항목 플랫 뷰는 수요 시
  상태 탭 보조 필터("항목만 보기")로.
- 체크 항목 개별 날짜 (Obsidian Tasks 문법) → 노트의 마감 취급(종료일, 2026-08-01 이후 §2)
  상속으로 대체.
- 헤더 요약 스탯 → 무압박 원칙으로 삭제.
- 명시적 잔디 히트맵 (GitHub식) → 장식적 풀잎 SVG로 완화했으나, 렌더 품질이 기대에 못 미쳐
  기각 (2026-07-31 1차 피드백) → 한 줄 블럭 스트립으로 교체했으나 헤더 배치상 애매해
  기각 (2026-07-31 2차 피드백) → 최종은 **주단위 그리드**(7행×N주, GitHub식이되 라벨·숫자·
  툴팁·클릭 없음, §3.1)로 채택(2026-07-31 3차 피드백)
  → **2026-08-01 QA에서 완전 제거.** 세 번의 기각(SVG→스트립→그리드) 끝에 채택했던
  그리드조차 실물로 보니 여전히 군더더기라 판단, 헤더에서 활동 시각화 자체를 없앴다
  (컴포넌트·테스트·i18n 키까지 삭제). "다그치는 지표 금지" 원칙은 표현 형태가 아니라
  이번엔 "형태 자체를 없앰"으로 관철된 것 — §3.1 참고.
- "기록축은 달력에 없다(헤더 잔디가 담당)" 서술 → 잔디 제거로 전제가 무효화되며 함께
  폐기, 달력에 흐린 점 레이어로 편입(2026-08-01 QA, §3.3).
- AI 생성 문구 → 보류 (JSON 스키마만 호환 유지).
- 활동 로그 테이블 신설 → 과설계, created/updated 근사로 충분.
- 연간 달력 뷰, 지도 클러스터링/경로, 모바일 → v1 제외. (연간 뷰는 2026-09-08 에 조망 전용으로
  회수 — §3.3.)
- **총괄(전 노트북) 스코프 + 독립 페이지(컨셉 A) → 컨셉 B(노트북 스코프+고정
  대시보드 탭)로 전환 (2026-07-31).** 근거: 실사용 노트북 ≤3, 폴더 그룹이 카테고리 담당,
  총괄의 인지 비용(이름 병합 칸반·조용한 전환·생성 대상 모호). 총괄 조망은 추후 스코프
  토글로 회수 가능.
- **마감(due_at) 축 → 종료일(end_*)로 병합 (2026-08-01).** 근거: "기간의 끝 = 처리 기한"이라
  같은 개념을 두 필드로 들고 있는 것은 중복이었다(과거 사건 종료와 작업 기한이 실질적으로
  같은 축인데 별도 컬럼·별도 커맨드·별도 팝오버 섹션으로 나뉘어 있었음). due_at 값은
  마이그레이션(v29)으로 end_* 에 흡수되고 컬럼은 드롭됐다. "마감 취급"(긴급도/빨강/⏰뱃지/
  상태탭 레인)은 저장 필드가 아니라 표시 규칙(종료일 풀 정밀도 + `[오늘-30일, +∞)`, §2)으로
  재정의 — 역사 노트가 실수로 "마감 지남"처럼 보이는 것을 원천 차단한다.
  → **2026-08-01 재그릴링에서 이 표시 규칙 자체가 다시 폐기됐다** (아래 항목 참고) — 위
  단락은 v29 시점 결정의 역사적 기록으로 남긴다.
- **"마감 취급"(긴급도/빨강/⏰뱃지/상태탭 레인) 표시 규칙 전면 폐지 → "알려줘"(remind)
  명시 opt-in 플래그로 교체 (2026-08-01, 오너 그릴링).** 근거: 종료일이 과거라는 사실
  *자체*가 신호였던 v29 규칙(`[오늘-30일, +∞)` 컷오프)은 여전히 "노트 날짜 = 압박"이라는
  전제를 깔고 있었다 — 역사/일상 기록 앱에서 과거 날짜는 정상이지 경보가 아니다(오너
  원 불만: 완료된 노트조차 "지남"으로 빨개지는 것도 이 전제의 부산물이었다). 새 모델은
  판정을 시스템의 날짜 계산이 아니라 **사용자의 명시적 의사**(remind 플래그)로 옮긴다 —
  아무 노트나 과거 종료일이면 자동으로 눈에 띄는 게 아니라, 사용자가 "이건 나중에 다시
  보고 싶다"고 표시한 노트만 뜬다. 부수 효과: 시간 윈도우 컷오프가 사라져 "30일 넘게
  지나면 조용히 사라지는" 혼란도 없어졌다(remind 를 켠 노트는 몇 년이 지나도 계속 핀
  된다 — 사용자가 직접 끄거나 완료 처리할 때까지). 완료 컬럼 예외는 유지(v29 규칙과
  동일 취지). 달력 탭의 ⏰/색상도 이번에 완전히 제거 — 달력은 애초에 "무압박" 원칙(§0)의
  적용 대상이었는데 마감 취급 표시가 그 원칙과 충돌하고 있었다. 마이그레이션 v30
  (`notes.remind`), 판정 지점 `repo::dashboard::is_pinned`/`board/status.ts::isPinned`.
