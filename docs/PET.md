# 펫 운영 정책 (SSOT)

펫(캐릭터 창 + 말풍선 창)의 **운영 계약**. 구현 디테일은 코드가 이긴다. 이 문서는
누가 무엇을 열고, 대화가 어디에 살며, AI가 꺼졌을 때 무엇이 남는지 고정한다.

관련: `docs/AI.md` §4.0(비서 챗) · `docs/TAURI-WINDOW.md`(투명 창) · `docs/DESIGN.md`(아크릴) ·
`src-tauri/src/pet_window.rs`(창 분리) · `docs/PET-IMAGE-MOTION-PIPELINE.md`(패키지 설치 · v1/v2 방언).

## 0. 컨셉 (2026-10-16 재정의)

> 왜 다시 적나: 2026-10-16 설정 > 펫 재설계 추천이 "화면 캡처 토글을 펫 페이지로 옮기자"고 했고,
> 오너가 "화면 캡처는 트레이 기능인데 왜 펫에 부르려고 하나"로 정정했다. 원인은 문서·문구가
> **펫 우클릭 메뉴 = 트레이 메뉴**라고 적어 둔 것(당시엔 사실이 아니었다 — 같은 날 실제로 통합, §0.3)과, 캡처 흐름이
> "펫 스크린샷"이라는 이름으로만 기록돼 있던 것이다. 이 절이 그 오해를 끊는 기준이다.

### 0.1 펫은 무엇인가

**트레이에 상주하는 Brise 를 바탕화면 위에서 보여 주는 동반자 캐릭터**다. 동봉 플러그인이고
기본 꺼짐(`pet_enabled`). 펫이 하는 일은 넷뿐이다.

1. **얼굴** — 스프라이트(패키지/무드 에셋)로 앱 상태를 보여 준다(생각 중·완료·실패).
2. **문** — 메인 창을 연다(우클릭 "열기"·트리플클릭, `pet_open_main` → `tray::show_and_focus`).
3. **말풍선** — 사이드바 챗 스레드의 **미러**(최신 3개, 1줄 입력)와 알림·클립 확인 카드.
4. **지름길** — 우클릭 메뉴(= 트레이 메뉴, §0.3)와 더블클릭 동작(새 노트 등). 우클릭 메뉴의
   항목은 **앱(트레이) 기능**이고 펫은 그 메뉴를 자기 위에 띄울 뿐, 그 기능의 소유자가 아니다.

### 0.2 펫이 아닌 것

- **챗이 아니다.** 대화 스레드·페르소나·기억·대화 기록은 **사이드바 AI 챗** 소유(설정 > AI >
  채팅, `AiChatSection` 안 `PetPersonaSection`). `pet_chat*`·`PetPersonaSection` 의 `pet_` 접두사는
  펫이 챗의 본 표면이던 시절의 **역사적 내부 식별자**다 — 이름을 보고 펫 소유로 읽지 않는다.
- **캡처 기능이 아니다.** 화면 저장은 트레이 상주 앱의 수집 기능이고, 토글은 설정 > 일반
  (`capture_screenshot_enabled`)에 있다. 진입점은 트레이 메뉴이고, 펫 우클릭은 같은 메뉴라 거기서도
  보일 뿐이다(§0.3·§0.5). 펫이 꺼져 있어도 동작한다.
- **트레이 메뉴의 주인이 아니다.** 우클릭 메뉴는 트레이 메뉴를 그대로 상속한다(§0.3) — 펫 전용
  항목 목록은 없다.

### 0.3 펫과 트레이 — 같은 메뉴 (2026-10-16 통합)

오너 결정(2026-10-16): **펫 우클릭은 트레이 우클릭과 정확히 같은 내용을 상속한다.** 항목 목록은
`tray.rs::build_tray_menu` **하나뿐**이고, 펫 우클릭은 `pet_menu_popup` 커맨드로 그 메뉴를 펫 창 위에
네이티브로 띄운다(`tray::popup_menu_on`). 클릭은 트레이 아이콘의 `on_menu_event` 가 받는다(Tauri 메뉴
이벤트는 전역). 펫 웹뷰(`PetApp.tsx`)에는 HTML 메뉴도, 두 번째 목록도 없다.

| 항목 | 언제 보이나 | 동작 |
|---|---|---|
| 열기 | 항상 | `show_and_focus` |
| 클립보드 저장 | 펫이 켜져 있고 보일 때 | Rust 가 클립보드를 읽어 `pet-menu-run {action:"clipboard",text}` → 펫 → 메인 창 다리 → 말풍선 확인 카드 |
| 화면 저장 | `capture_screenshot_enabled` | 펫 창이 있으면 `pet-menu-run {action:"capture"}` → 기존 카드 흐름, 없으면 Rust 직행(캡처 → 폴더 저장 → OS 알림 → 인박스 노트 자동 생성). `docs/CAPTURE.md` |
| 새 세션 열기 | 펫이 켜져 있고 보이며 **AI 챗을 쓸 수 있을 때**(`commands::pet::chat_available` — 챗과 같은 `privacy_gate_ok` 판정, 로컬 ollama 는 동의 없이도 열림. `ai_enabled`·`ai_provider`·`ai_endpoint` 가 바뀌면 메뉴를 다시 짠다) | 사이드바 챗 "새 세션"과 같은 커맨드 `pet_session_new`(지금 대화 보관 → 새 라이브 세션). Rust 가 직접 부르고(백엔드 전용 동작), 사이드바·말풍선은 `pet-chat-updated` 로 다시 읽는다. 확인을 묻지 않는다 — 보관이지 삭제가 아니고(세션 목록에서 다시 연다) 빈 대화면 아무것도 보관하지 않는다. 응답 대기 중에 눌러도 그 답은 **턴이 시작된 세션**에 저장되고(`pet_chat_turn` 이 시작 세션 id 를 잡고 사용자 행을 턴 시작 때 바로 써 두므로 그 세션은 비어 있지 않아 보관된다. 실패해도 실패 행이 같은 세션에 남는다), 대기 중이던 화면은 대기를 끊고 새 라이브를 다시 읽는다(`isSessionSwitch`) |
| 펫 표시/숨기기 | `pet_enabled` | `pet_visible` 토글(펫에서 누르면 = 예전 "펫 끄기") |
| 동기화 상태 · 접속 주소 복사 · 종료 | 항상 | 그대로 |

한쪽에서만 의미 있는 항목은 **같은 모델 안의 조건**으로 처리한다(예: 클립보드 저장은 확인 카드가 펫
말풍선에 뜨므로 펫이 있을 때만). 예전 펫 전용 항목 "대화 지우기"는 없어졌고, 그 자리를 **"새 세션 열기"**가
대신한다(오너 2026-10-16 — 펫 말풍선은 챗 미러라 거기서 대화를 끊을 손잡이는 필요하지만, 지우기가 아니라 보관 후
새로 시작). 대화 기록 지우기 자체는 여전히 설정 > AI > 채팅(§0.2). 메뉴는 `pet-theme-changed`(`capture_screenshot_enabled` 변경 포함)와
펫 on/off(`reconcile`)에 다시 짠다.

트레이가 펫에 대해 쥔 것은 **표시/숨기기**(`tray-pet-toggle` → `pet_visible`)뿐이고, 마스터(`pet_enabled`)는
설정 > 펫만 바꾼다. 의존 방향은 **펫 → 트레이**: 펫 창은 앱 프로세스가 살아 있어야 살므로 `close_to_tray` 가
꺼져 있으면 설정 > 펫이 "앱을 닫으면 펫도 사라집니다"(`pet_needs_tray`)를 띄운다.

### 0.4 설정 > 펫 페이지의 경계

**판정 규칙**: 펫을 꺼도 의미가 있는 기능은 펫 페이지에 오지 않는다. "펫 메뉴에서 보인다"·"키가
`pet_` 로 시작한다"는 근거가 아니다.

이 페이지가 **소유하는 것**:

| 무엇 | 키·커맨드 |
|---|---|
| 마스터 토글(히어로 우측) | `pet_enabled` / `pet_set_enabled` |
| 캐릭터 — 패키지 갤러리·설치·삭제·선택 | `pet_package_*`, `pet_selected_package` |
| 동작 — 더블클릭 동작(대화·새 노트·없음) | `pet_dblclick_action` |
| 화면 위치 — 모니터 미니맵 앵커·현재 위치·기본 위치 | `pet_set_position`·`pet_position_reset`, `pet_pos_x/y` |
| 트레이 상주 경고 한 줄 + [트레이로 닫기 켜기] | `close_to_tray` 는 일반 소유 — 버튼은 같은 `setCloseToTray` 를 부르는 원격 컨트롤(켜기만) |

무드별 개별 에셋(`pet_assets` / `pet_asset_*`)은 2026-10-16 에 UI 에서 걷혔다(§0.6-4) — 소유가
아니라 **휴면 데이터**다.

**소유하지 않는 것** (펫 페이지에 넣지 않는다):

| 무엇 | 사는 곳 |
|---|---|
| 화면 저장 토글 `capture_screenshot_enabled` · 저장 폴더 `capture_screenshot_dir` | 설정 > 일반(앱 동작) |
| 페르소나 · 챗 기억 · 대화 기록 지우기 | 설정 > AI > 채팅 |
| AI 마스터 `ai_enabled` | 설정 > AI 제공자 첫 줄 |
| 트레이 상주 `close_to_tray` | 설정 > 일반 |
| 펫 표시/숨기기 `pet_visible` | 트레이 · 타이틀바 플러그인 아이콘(별도 행 없음, PLAN-2026-09-15 P8) |
| 결제문자 캡처 `capture_ledger_enabled` | 연결 > 문자 파싱(`docs/CONNECT.md`) |

### 0.5 화면 저장 — 갭 해소 (2026-10-16)

컨셉(오너 2026-10-16): **트레이 상주 앱의 기능**. 같은 날 기록한 갭 셋은 모두 닫았다.

- ~~진입점이 펫 우클릭 하나뿐~~ → 트레이 메뉴 "화면 저장"(`capture_screenshot_enabled` 일 때). 펫 우클릭은 같은
  메뉴(§0.3)라 거기서도 보인다. **펫을 꺼도 캡처된다.**
- ~~확인 카드가 펫 말풍선에만~~ → 파일은 **항상 저장 폴더**에 남는다(설정 > 일반 "화면 저장 폴더",
  `capture_screenshot_dir`, 빈 값 = `<사진>/Brise`) + OS 알림(본문 = 저장 경로). 펫이 떠 있으면 그 위에 기존
  말풍선 카드(노트에 추가)가 얹힌다. 펫이 없으면 **인박스 노트가 자동으로 생긴다**(오너 2026-10-16) — 카드와
  같은 커맨드(`pet_note_create` → `attachment_add_bytes`)를 타지만 **AI 비전 요약은 돌리지 않는다**(오너
  2026-10-16, 본문 = 출처 한 줄 `화면 캡처: <창 제목>`, `commands::pet::capture_to_inbox`). 이미지가 AI
  제공자로 나가는 경로는 펫 카드 하나뿐이다. 단일 관문은 `tray::capture_to_folder`.
- ~~문구가 "둘은 같은 메뉴"라고 사실과 다름~~ → 이제 사실이다. 문구는 "트레이 메뉴에 화면 저장 추가 / 펫이 켜져
  있으면 펫 우클릭에도"로 고쳤다(ko/en/fr).

내부 식별자(`pet_screenshot_capture`, `petScreenshotBridge`)는 개명하지 않는다.

### 0.6 설정 > 펫 재설계 (**완료** 2026-10-16, 디자인 보드 `set-pet` "엉망임, 다시해야")

위 경계 안에서만 손댄다. 지난 추천 중 **"화면 캡처 토글을 펫 페이지로" 는 철회**한다(§0.4).

페이지 구조(`PetSection.tsx`): 히어로 마스터 토글 → **꺼져 있으면 한 줄 안내만**(그룹·빈 카드 없음)
→ 켜져 있으면 트레이 경고(`close_to_tray` 꺼졌을 때만) + 카드 셋.

| 카드 | 내용 | 파일 |
|---|---|---|
| 캐릭터 | 큰 미리보기 + 무드 세그먼트(평상시/기쁨/알림, **표시 전용**) + 갤러리 + "+ 캐릭터 추가" 메뉴 | `pet/PetPackageGallery.tsx` |
| 동작 | 더블클릭 동작 + 페르소나 **링크 행**(→ AI > 채팅, `onNavigate("ai_chat")`) | `pet/PetReactionSection.tsx` |
| 화면 위치 | 모니터 미니맵(앵커 9점 + 현재 위치 사각형) + 글자 버튼 "기본 위치로" | `pet/PetPositionPicker.tsx` |

결정(오너 위임, 2026-10-16):

1. **미리보기 + 갤러리를 한 카드** — 미리보기는 **실제 펫 창 컴포넌트(`PetSprite`)를 그대로**
   그린다. 예전 `PetPreview` 는 펫 창의 우선순위(패키지 > 무드 에셋 > SVG)를 손으로 복제하고 있었다
   — 이제 복제가 없어 어긋날 수 없다. 갤러리의 "기본 캐릭터" 타일도 스마일 아이콘이 아니라
   실제 기본 SVG(`PetSvg`, 파란 새)를 그린다(고른 것과 뜨는 것이 달라 보이던 결함).
2. **추가 메뉴 하나** — 아이콘 버튼 셋(파일·Codex·URL)을 "+ 캐릭터 추가" 메뉴 하나로 합치고
   **폴더**를 넣었다(OS 대화상자가 파일·폴더를 한 번에 못 고른다 — 항목 둘, 같은 설치 경로).
   PNG/GIF 도 이제 이 경로(`pet_package_install`, idle-image 방언)로만 들어온다. 드롭 존은 캐릭터
   카드 전체.
3. **미니맵에 현재 위치** — 저장된 `pet_pos_x/y` 를 펫 창 크기(160×180) 사각형으로 그린다(자유
   위치 포함). 앵커 점도 10/50/90% 근사가 아니라 그 앵커에 놓인 창의 실제 중심에 찍어 사각형과
   축척이 맞는다. 펫 이동 이벤트가 없으므로 **설정 창 포커스가 돌아올 때 `settings_get_all` 을
   다시 읽는다**(페이지 전체가 한 번 읽어 내려준다). 이동 실패는 토스트 + 롤백.
4. **무드별 파일 표 제거** — `PetAssetGrid` 와 그 상태(PNG 대기·프레임·주기)를 지웠다. 저장된
   `pet_assets` 는 **휴면 유지**: RETIRED_KEYS 로 보내지 않고, 펫 창(`PetSprite.usePetAsset`)이
   패키지 미선택 시 계속 읽어 그린다. 새로 등록하는 UI 만 없다. 커맨드 `pet_asset_*` 는 남는다
   (`pet_assets_list` 는 펫 창이 쓴다). 완전 퇴역은 실사용에서 등록분이 사라졌다고 확인된 뒤.

## 플러그인 표면 (P0, 2026-08-27)

펫은 **동봉 플러그인**이다(용어: `docs/GLOSSARY.md`, 규약: `PLAN-2026-08-27-space-plugin-rebuild` §2).
메인 앱 기능이 아니라 설정에서 켜는 옵션 기능이며, 표면은 넷뿐이다.

| 표면 | 위치 |
|---|---|
| 마스터 토글 | 설정 키 `pet_enabled`("0"/"1"), 기본 off. 꺼져 있으면 아래 표면이 전부 사라진다 |
| 설정 | 설정 창 좌측 레일 **"플러그인" 그룹 > 펫**(맨 아래). 페이지 id 는 `pet` 그대로 |
| 진입 아이콘 | 메인 타이틀바 우측 그룹의 **맨 앞 "플러그인 아이콘 영역"** — 뒤 구분선으로 기능 아이콘과 갈린다 |
| 트레이 | `tray-pet-toggle`(`tray::reconcile()` 단일 지점) |

프런트 코드는 `src/plugins/pet/`(창·스프라이트·챗 UI)와 `src/plugins/pet/bridge/`
(메인 창이 대행하는 다리 12종 — 펫 창은 `PET_ALLOWED_COMMANDS` 밖을 못 부른다).
설정 섹션 컴포넌트는 설정 창 소유라 `src/components/settings/` 에 남는다.
Rust(`pet_window.rs`·`commands/pet.rs`·`repo/pet`)는 이미 파일 단위로 분리돼 있어 옮기지 않는다.
`main.tsx` 의 `#/pet`·`#/pet-bubble` 분기는 **dynamic import 전용** — static import 를 하나라도
추가하면 펫 창이 메인 청크를 통째로 먹는다.

## 창

| 창 | 라벨 | 역할 | 크기 |
|---|---|---|---|
| 메인 | `main` | 노트/대시보드/설정. 원본 UI. | 사용자 지오메트리 |
| 캐릭터 | `pet` | 스프라이트만. **리사이즈 금지.** | 160×180 고정 |
| 말풍선 | `pet-bubble` | 알림 / 클립 카드 / **가벼운 대화** | 알림=내용 높이, 대화=압축 고정 |

캐릭터와 말풍선은 **별 웹뷰**다. 말풍선이 열려도 펫은 움직이지 않는다.

## 메인 창 열기

다음 경로는 **전부** `tray::show_and_focus` 한 함수를 탄다.

- 트레이 좌클릭 / 더블클릭 / 메뉴 "열기"
- 단일 인스턴스 재실행
- 펫 우클릭·트리플클릭 `pet_open_main`
- 말풍선 노트 칩 / 계획 칩 / 겹침 검토 (`pet_open_main` + 이벤트)

`show_and_focus`는 `unminimize` → `show` → 안 보이면 `center` 후 재시도 → `set_focus`.
실패를 삼키되 `eprintln`으로 남긴다.

Acrylic(`window_set_effect`)은 **창이 보인 뒤에만** 건다. 숨긴 HWND에 바르면 핸들이
깨져 메인 창이 테두리만 남거나 목록에서 사라진다(`applySurfaceEffectAfterShow`).

이 규칙은 오래 **이 문서에만** 있었고 지키는 것은 호출부들이었다. 그래서 새 팬아웃 경로가
생길 때마다 되살아났다 — 마지막이 별도 설정 창(2026-08-14)이다: 메인이 트레이에 숨은 동안
설정 창에서 테마·표면을 바꾸면 `window_set_effect` 가 펫이 아닌 **모든 창**에 걸었고, 그
팬아웃이 숨은 메인의 핸들을 죽여 트레이/펫에서 창이 열리지 않았다. 이제 규칙은
`commands::window::should_apply_effect` 가 강제한다(펫 제외 · 부른 창은 항상 · 그 밖은 보일
때만). 호출부에서 다시 지킬 필요는 없다.

펫 창은 `settings_get_all` 금지(`PET_ALLOWED_COMMANDS`). 테마·표면·AI 켜짐은 `pet_theme`만.

## 대화 스레드

사이드바 챗이 **본 표면**. 펫 말풍선은 같은 `pet_chat*` 스레드의 **미러**.

| | 사이드바 | 펫 말풍선 |
|---|---|---|
| 스레드 | `pet_chat` / `pet_chat_history` | 동일 |
| 도구·프리셋·세션·드롭 | 있음 | **없음** (사이드바로) |
| 보이는 말풍선 | 전체 | **최신 3개** |
| 입력 | 2줄 textarea | **1줄** |
| 표면 | 사이드바 in-flow | `.overlay` + `data-surface` 상속 |

버블 마크업은 `src/plugins/pet/ChatBubble.tsx`, 입력은 `src/plugins/pet/ChatComposer.tsx` — 양쪽이 이걸 쓴다.

## AI 게이트

`ai_enabled === false`일 때:

- 사이드바: 채팅 탭 숨김(기존).
- 펫 말풍선: 입력은 연다. 전송은 `pet_chat`을 부르지 않고, 힌트를 보여 **메모 저장**만 된다.
- `pet_theme.ai_enabled`로 부팅하고 `pet-theme-changed`로 산다. 프라이버시 게이트 거부는 폴백.

## 스타일

말풍선 창은 OS 투명. `usePetTheme`이 `data-theme` / `data-surface` / `--sheet-alpha` /
`--accent` / `--fs`를 심는다. 대화 패널은 `.overlay`(flat=불투명, acrylic=시트 틴트).
캐릭터 창은 배경을 칠하지 않는다(스프라이트만).

## 하지 말 것

- 펫 창에서 `settings_get_all` / 노트 mutate 커맨드 직접 호출.
- 말풍선에 사이드바 도구·세션 목록을 복제.
- 캐릭터 창을 대화 크기로 키우기.
- 숨긴 메인 창에 Acrylic을 다시 바르기.
- 펫이 지름길로 부르는 앱 기능(화면 저장 등)의 설정을 펫 페이지로 끌어오기(§0.4 판정 규칙).
- 펫 웹뷰에 트레이와 다른 두 번째 우클릭 목록 만들기(§0.3 — 목록은 `build_tray_menu` 하나).
