이 문서가 Brise의 **용어 단일 기준**이다. UI 문구(i18n), 스펙/문서, 커밋 메시지, 에이전트 프롬프트,

### AI 3계층 (2026-08-30 확정)

"AI supported note" 를 말할 때 쓰는 어휘. SSOT 는 `docs/AI.md` §1, 구현은
`src/lib/aiCapabilities.ts` 의 `AiCapabilityTier`.

| 한국어 | 코드 식별자 | 정의 | 원본에 무슨 일이 |
| :-- | :-- | :-- | :-- |
| **손질** | `refine` | 내가 쓴 것을 읽고 다듬는다 | 원본 보존, 결과는 새 섹션 |
| **정돈** | `organize` | 구조·메타데이터를 붙인다 | 제안 → 확인 → 적용 |
| **수집** | `gather` | 바깥의 것을 들여온다 | 원문은 사료 패널에 보존 |

"정리"는 **쓰지 않는다** — 손질(다듬기)과 정돈(구조 붙이기) 둘 다로 읽혀서 어느 계층인지
가려지기 때문이다. 기존 액션 이름 `organize`(본문 다듬기 프리셋)와 계층 `organize`(정돈)가
철자만 같고 뜻이 다르다는 점에 주의한다 — 그 프리셋은 계층상 **손질**이다.

## 금지/치환 규칙

- "워크스페이스", "workspace" (사용자 노출 문구) → **노트북 / Notebook**
- "홈", "Home" (화면 지칭) → **대시보드 / Dashboard**
- "작업" 탭, "Tasks", "상태" 탭 (대시보드 탭 지칭) → **칸반 / Kanban** (내부 식별자 `board` 계열은 유지). 칸반 내부의 열만 "상태 / Status"
- "공유(share)" → **내보내기(export)** (이전 결정 유지)
- "루틴" (폴더별 AI 작업을 가리킬 때) → **자동화 / Automation**. 반복 노트 체크를 가리킬 때 → **습관 체크**. 새 내부 식별자에 `routine_*` 금지(기존 습관 체크·MCP 도구와 충돌)
- "자동화" (기존 AI 기능 전반을 가리킬 때) → **AI 기능 / AI features**. "자동화"는 위 자동화 기능에만 쓴다. 설정 > AI 의 정책 단계는 **AI permission level / Niveau d'autorisation IA**(ko "AI 기능 레벨")
- "AI 액션", "AI 작업" (저장된 프리셋을 가리킬 때) → **AI 프리셋 / AI preset**. AI 메뉴 버튼 자체의 이름(`editor.ai_menu_title` "AI 작업")은 프리셋이 아니라 실행 메뉴라 이 규칙 밖이다

## 코드 식별자 정책

기존 코드는 `workspace_id`, `useWorkspacesStore`, `HomeTab` 등 옛 명칭을 광범위하게 쓴다.
DB 컬럼·IPC 커맨드 이름까지 한 번에 바꾸는 것은 마이그레이션·동기화 호환성 비용이 크므로:

1. **사용자에게 보이는 모든 것**(i18n 문자열, 문서, 릴리스 노트)은 즉시 새 용어를 따른다.
2. **새로 만드는 코드**는 새 용어로 명명한다 (`notebook*`).
3. **기존 내부 식별자**(DB 스키마, 커맨드 이름, 스토어 키)는 별도 리네이밍 작업으로 계획적으로 처리한다.
   섞여 있는 동안 혼동을 막기 위해, 옛 이름을 만지는 코드에는 "= 노트북" 주석을 남긴다.
