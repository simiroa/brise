# Brise 컨셉

> 한 줄: **지식의 무덤이 아닌 정원으로.** 같은 기록을 여러 축에 겹쳐 보면서, 인사이트는 사람이 직접 기른다.

이 문서는 제품 방향의 SSOT다. 기능을 넣고 뺄 때의 판단 기준으로 쓴다.
(옛 한지·청자·먹 비유는 폐기됐다. `PRODUCT.md`·`docs/DESIGN.md`에 남은 그 표현은 이 문서와 어긋나는 낡은 서술이다.)

## 1. 문제 — 쌓기만 하면 무덤이 된다

기록 앱은 쌓는 데는 쉽고 다시 쓰는 데는 약하다. 쌓인 메모는 한 줄짜리 목록으로만 보이고, 서로 닿는 자리는 보이지 않는다. 결국 다시 열지 않는 무덤이 된다.

## 2. 핵심 주장

**인사이트는 결과물을 읽어서 생기지 않는다. 여러 결정과 사건을 겹쳐 놓고 보면서 생각을 넓히는 과정에서 생긴다.**

그래서 Brise가 하는 일은 둘이다.

1. 기록을 **여러 축**으로 보여 줘서 겹쳐 볼 수 있게 한다.
2. 겹쳐 보고 연결하고 결론 내리는 **과정을 사람 손에 남긴다.**

쓰임새는 두 가지다: 학습한 내용을 정리하기, 여러 결정을 메모해 쌓아 가기.

## 3. 축

같은 노트가 축마다 다른 이웃을 만난다.

| 축 | 화면 | 던지는 질문 |
|---|---|---|
| 시간 | 타임라인 · 달력 | 그때 무엇을 알고 있었고, 무엇을 결정했나 |
| 장소 | 지도 | 어디서 있었던 일인가 |
| 상태 | 보드 · 할 일 | 지금 어디까지 왔나 |
| 관계 | 관계도 | 무엇이 무엇과 이어지나 |
| 구조 | 노트북 → 폴더 → 노트 → 섹션 | 어떤 주제 아래 있나 |
| 말 | 검색 | 이 낱말이 어디에 나왔나 |

예: "이 도구를 쓰기로 했다"는 결정 노트 하나를 타임라인에서는 앞뒤 사건과, 보드에서는 아직 안 끝난 일과, 관계도에서는 근거가 된 학습 노트와 나란히 놓고 본다.

## 4. 역할 분담

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| **사람** | 쓰기, 연결하기, 겹쳐 보며 의미 찾기, 결론 내리기 | |
| **앱** | 축 제공, 검색, 복원·백업, 폰 동기화 | 의미 판단 |
| **AI** (선택) | 받아쓰기, 요약·정리 제안, 노트 근거 채팅 | 사람 대신 인사이트를 확정해 쓰기 |

## 5. LLM 위키와 무엇이 다른가

LLM 위키는 2026년 4월 Karpathy가 공개한 방식으로, 모델이 원본 자료를 마크다운 위키로 컴파일해 유지하고 사람은 출처를 모으고 질문한다.

| | LLM 위키 | Brise |
|---|---|---|
| 정리·연결하는 쪽 | 모델 | 사람 |
| 사람이 보는 것 | 모델이 만든 **출력** | 자기 기록을 **여러 축에 겹친 화면** |
| 인사이트가 생기는 곳 | 결과물을 읽을 때 | 겹쳐 보고 연결하는 과정 |
| 산출물의 성격 | 모델이 컴파일한 위키 | 사람이 쓴 기록과 연결 |
| 잘 맞는 일 | 방대한 자료의 폭넓은 정리 | 자기 결정·학습의 축적과 재해석 |
| 위험 | 중요도 판단이 모델에게 넘어감 | 사람이 안 쓰면 아무것도 안 쌓임 |

일반 노트 앱(Obsidian 등)과의 차이는 다른 곳에 있다. 그쪽도 사람이 쓰지만 보는 방식은 대체로 목록과 링크 하나다. Brise는 **같은 기록을 시간·장소·상태·관계 축으로 교차해 보게 하는 것**이 차별점이다.

## 6. 우선순위

README의 세 원칙과 같다.

1. **교차해서 본다** — 축과 겹쳐 보기
2. **쾌적하다** — 로컬 SQLite, 오프라인, 부팅·검색 성능은 기준선으로 관리
3. **내 데이터는 내 것** — 특정 클라우드·에이전트에 종속되지 않는다. 폰 동기화(QR·Tailscale), 가져오기·내보내기(export)

그다음 순서로 **밖으로 이어지기**(폰·외부 앱)와 **에이전트 친화**(노트 근거 채팅, 외부 에이전트용 CLI·MCP 서버 `cli/`)를 둔다.

## 7. 판단 규칙 (제안)

- 새 기능이 **사람이 겹쳐 보는 과정을 대신하면** 의심한다. 보조(제안·초안)는 되고 대체는 안 된다.
- 새 축은 **이미 있는 기록을 다르게 보여 주는 것**이어야 한다. 새 데이터를 요구하면 축이 아니라 기능이다.
- AI 산출물은 사람이 받아들이기 전에는 기록이 아니라 제안이다.

## 8. 열린 질문

- "AI는 저자가 아니다"의 선: 요약·정리 제안까지는 되는데, 외부 에이전트(MCP)가 노트를 만드는 것은 어디까지 허용하나.
- 사람이 쓴 것과 AI가 쓴 것을 기록에서 구별해 표시할지.
- 축 사이를 오가는 경험(한 노트에서 다른 축으로 바로 넘어가기)을 얼마나 일급으로 다룰지.
